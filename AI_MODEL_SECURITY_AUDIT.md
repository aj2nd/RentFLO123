# AI Model Security Audit

RentFLO’s model integrations were reviewed for **prompt construction, request authority, output persistence, and output rendering**. The hardening change keeps the server-owned policy in a system message and places every client message, stored transcript, account field, creative brief, and transcription inside an explicitly labelled **untrusted data** envelope. Model responses are treated as untrusted plain text, bounded, control-character filtered, and rendered by React as text rather than HTML.

| Integration | Reachability at audit | Previous trust concern | Protection applied |
|---|---|---|---|
| `/api/chatbot` | Registered; authenticated and account-rate-limited. The retained `AIChatBot` component is not mounted in the current UI. | The client could submit a `system` role and supply its own role/name/property/rent context. Conversation turns were forwarded with their client-selected roles. | The strict schema now accepts only `user` and `assistant` labels. The server obtains role/property/rent from authenticated records, sends fixed server-owned instructions as the only system message, and encloses the whole transcript/context in a single untrusted-data user message. |
| Legacy text conversations | Dormant: its route registrar is not imported by server startup; admin-only if enabled. | Stored message roles and content were forwarded directly as model roles. | Fixed instructions, an untrusted conversation envelope, and bounded server-side response sanitization. |
| Legacy voice conversations | Dormant: its route registrar is not imported by server startup; admin-only if enabled. | Transcriptions and stored roles were sent directly to the audio model. | Fixed instructions, an untrusted transcript envelope, and bounded/filtered transcript output before SSE and persistence. |
| Shared voice/TTS helpers | Retained helper code; no active caller was found. | TTS interpolated arbitrary text into an imperative instruction; voice helpers had no fixed RentFLO policy. | Voice calls now prepend fixed instructions. TTS passes `{ "text": ... }` as isolated JSON data under a constrained server instruction. |
| Image generation/editing | Dormant: image routes are not imported by server startup; no consumer was found. | Creative prompt text was passed through without an explicit data boundary. | The route and shared helpers wrap the creative request in a fixed image-only, untrusted-data prompt. Generated bytes are not executed; no current browser renderer consumes this endpoint. |
| Speech-to-text | Retained helper; no active caller was found. | A transcription is untrusted text if later passed to a model. | Its downstream conversation path now wraps transcript history as untrusted data; the transcription helper itself does not execute or render text. |

## Prompt-boundary design

> **Only server constants occupy the model’s `system` role.** Every browser-supplied or stored value is serialized as quoted data in a separate `user` message. The policy explicitly says that prompt-injection content, role labels, URLs, and instructions inside that data cannot override the system policy.

The primary chatbot no longer accepts `userContext` from the browser. It derives the user’s role and first accessible property record from the authenticated server session. Those database values are still placed in the untrusted-data envelope because property names and addresses can contain user-created text.

## Untrusted output handling

The server strips control and bidirectional-override characters and enforces a 12,000-character maximum for streamed or persisted chat output. The client applies the same filtering before accumulating and rendering streamed text. Its model response is used only as a JSX text child; no `dangerouslySetInnerHTML`, `innerHTML`, executable URL, dynamic script, or evaluator is used in the chatbot path. React therefore escapes markup such as `<script>` as visible text rather than executing it.

## Verification

Run `pnpm exec tsx scripts/verify-ai-model-security.ts` after any AI integration change. The verifier checks the system/data boundary, rejects client system messages, confirms server-derived account context, tests the output sanitizer, and scans the primary client renderer and retained integrations for the required safeguards.

## Operational note

Prompt injection is a model-behavior risk that cannot be eliminated solely by prompt wording. RentFLO’s design therefore avoids model tools and side effects in these flows: responses are informational text only, and the app does not let model output authorize payments, modify records, execute code, or navigate users automatically.
