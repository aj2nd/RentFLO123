# RentFLO Client Secret & API Boundary Audit

**Audit date:** 24 August 2026  
**Scope:** Tracked frontend source, current production bundle, and all Git history revisions touching `client/` or `public/`.

## Executive result

No API key, secret, private key, or hard-coded provider token was found in the current frontend source, current built frontend artifacts, or the scanned client/public history. The client uses only development-mode flags (`import.meta.env.DEV`); no `VITE_*` secret-bearing configuration is referenced. Provider credentials remain in server-side `process.env` access only.

## Findings and remediation

| Finding | Location | Risk | Remediation |
|---|---|---|---|
| UPI QR images were generated by a third-party browser request. The request did **not** carry an API key, but it sent UPI payment data to `api.qrserver.com`. | `client/src/components/PayRentButton.tsx` | Privacy and external-dependency exposure | Replaced with the authenticated same-origin endpoint `GET /api/payments/upi-qr`. `server/routes.ts` now creates the PNG in process using `qrcode`; the browser opens only a RentFLO URL. |
| Environment files were not ignored by Git. No `.env` file is currently present or tracked, but a future file could have been accidentally staged. | `.gitignore` | Preventive configuration risk | Added `.env` and `.env.*` ignore rules while allowing a safe `.env.example` template. |

## Verified backend ownership

| Integration | Client behavior | Server-side ownership |
|---|---|---|
| Google OAuth | Navigates only to RentFLO `/api/login`. | OAuth client secret and session handling remain in `server/replit_integrations/auth/`. |
| Cashfree | The browser requests RentFLO payment endpoints; it contains no Cashfree credential. | Cashfree app ID and secret are read only in `server/routes.ts`. |
| Didit KYC | The browser requests RentFLO KYC endpoints and follows a server-issued hosted URL. | API key, workflow ID, and webhook secret stay in `server/didit.ts`. |
| AI chat | The browser posts only to `/api/chatbot`. | OpenAI integration configuration stays server-side in `server/routes.ts`. |
| Push notifications | The client fetches the public VAPID key from RentFLO. | The VAPID private key remains server-side in `server/push.ts`. |

## Verification performed

The audit scanned 111 tracked client/public files, the compiled production bundle, and the Git history for those client/public paths. It found zero credential-pattern matches in all three. A post-remediation rescan confirmed that `api.qrserver.com` is absent from client source and that the frontend contains no direct provider request with a secret.

> Public identifiers such as OAuth client IDs, VAPID public keys, static Google Fonts requests, schema metadata, Instagram links, and `upi://` deep links are not provider secrets. They were retained because they do not embed a private API credential. The QR service was still removed to minimize external handling of payment data.

## Operational note

Keep actual production values exclusively in Railway environment variables. Do not place real values in `VITE_*` variables, `client/`, `.env.example`, or any committed documentation.
